本轮属于设计落档阶段。

输入：
1. 已经确认的软件设计
2. 已经确认的 Mermaid 图表
3. 项目目录

要求：
1. 不要重新设计。
2. 不要改变已确认设计的含义。
3. 不要拆开发任务。
4. 不要写代码。
5. 在项目 docs 下创建或更新设计文档。
6. 如果项目已有 docs 目录和文档命名风格，请优先遵守现有风格。
7. 如果没有现有风格，建议命名为 docs/design-当前功能名.md。
8. 设计文档是给人类存档和后续项目计划依赖的正式文档，只能写到项目 docs 下，不要写到 docs/superpowers。

文档必须包含：
1. 设计方案
2. 取舍说明
3. 系统边界
4. 模块划分
5. 核心流程
6. 接口设计
7. 数据设计
8. 错误处理
9. 权限设计
10. 并发与幂等设计
11. 部署与回滚设计
12. Mermaid 图表
13. 明确不做的内容

写完后检查：
1. 是否有占位符
2. 是否有前后矛盾
3. 是否缺少图表
4. 是否保留未确认假设
5. 是否夹带未确认的新设计

输出：
1. 设计文档路径
2. 写入内容摘要
3. 自查结果
4. 是否可以进入开发任务拆分
