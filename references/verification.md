Use skill `superpowers:verification-before-completion`.

请委派给 reviewer agent `verification-reviewer` 检查验证证据是否足够。

本轮属于完成前验证阶段。
在声明任务完成前，请先做验证，不要凭感觉说“完成”“应该没问题”。

验证要求：

1. 先明确本次要验证的对象：
   - 需求澄清是否完成
   - 设计文档是否已经写入项目 docs
   - 开发计划是否覆盖设计
   - 代码改动是否满足任务验收标准
   - 集成测试是否已经完成
   - 集成测试是否覆盖本次新增或修改的核心业务流程
   - 未覆盖的核心业务流程是否已经记录原因并获得用户确认
   - 测试、lint、构建或其他必要检查是否通过
2. 明确哪些命令或检查可以证明任务完成。
3. 运行必要的验证命令，并读取完整输出和退出码。
4. 如果是文档类任务，请检查文档是否真实存在，内容是否包含必要章节和图表。
5. 如果是代码类任务，请运行对应测试、lint、构建或项目约定的验证命令。
6. 对照需求、设计、开发计划和验收标准逐项确认。
7. 如果有失败项或缺失项，直接说明实际状态，不要声称完成。
8. 只有验证通过后，才能说明任务完成。
9. 如果测试或验证需要用户提供 API key、token、账号、私有服务、人工登录、付费资源、真实第三方环境或类似外部资源，必须停止并等待用户反馈；不要跳过、伪造、mock 成已验证，除非用户明确同意把该项记录为未验证。

输出格式：

1. 验证对象：
2. 验证命令或检查项：
3. 验证结果：
4. 未通过或未验证的内容：
5. 是否可以声明完成：
